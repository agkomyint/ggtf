# Design: GGTF (Ghost Gibberlink Transmission Framework)

## Overview

GGTF has one Rust core that does all signal processing, framing, error correction, cryptography and channel simulation. The same core is compiled three ways:

- to **WebAssembly** for the browser app,
- as a **Python extension** (PyO3, built with maturin) for training and benchmarks,
- as a **native library** for Rust unit and property tests.

Having one implementation means the browser, the training data and the benchmarks can't drift apart.

The browser app is Next.js running on Bun. Audio input and output run in an AudioWorklet. Decoding runs in a Web Worker that loads the WASM core and, when enabled, the ONNX model.

Numbers in this document (bands, symbol lengths, timeouts, targets) are starting values. The benchmark is the source of truth, and values are tuned from its results.

## Architecture

```
 ┌──────────────── Station (browser tab) ────────────────┐
 │  React UI (chat, spectrogram, status)                 │
 │        ▲ events            │ commands                 │
 │        │                   ▼                          │
 │  Link worker (Web Worker)                             │
 │    ggtf-wasm: Session ▸ Link ▸ Framer ▸ Modem         │
 │    optional: onnxruntime-web ML symbol decoder        │
 │        ▲ input samples     │ output samples           │
 │        │ (ring buffer)     ▼                          │
 │  AudioWorklet (capture + playback, 128-sample blocks) │
 └────────┬──────────────────────────────▲───────────────┘
          ▼ speaker                      │ microphone
                 ~~~~~~~~ air ~~~~~~~~
```

Samples move between the AudioWorklet and the worker through a `SharedArrayBuffer` ring buffer. That requires cross-origin isolation, so Next.js sends `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`. This also lets ONNX Runtime Web use threads. If isolation isn't available, the station falls back to `postMessage` transfers.

## Components

### 1. Modem (physical layer), in `ggtf-core::modem`

**Modulation: M-ary FSK (MFSK).** Each symbol is one tone out of M tones. MFSK holds up well in open air because the receiver only needs to find which tone is strongest, not measure phase or exact amplitude. Spectrogram symbols are also easy for a CNN to learn.

- Sample rate: 48 kHz.
- **Profiles** (initial values, tuned by benchmark):

| Profile | Tones (M) | Bits/symbol | Symbol length | Parallel tone groups | RS parity |
|---|---|---|---|---|---|
| `wraith` (slowest, most robust) | 16 | 4 | 40 ms | 1 | high |
| `specter` | 16 | 4 | 20 ms | 2 | medium |
| `banshee` (fastest) | 32 | 5 | 10 ms | 4 | low |

  Parallel tone groups send several MFSK symbols at once in separate sub-bands. That multiplies throughput when the room is quiet.
- **Bands:**
  - Half-duplex: one shared band, initially 1.5 to 7 kHz.
  - Full-duplex: caller band about 1.5 to 4 kHz, answerer band about 4.5 to 7 kHz, with a guard gap between them. This follows the Bell 103 idea of originate and answer frequencies.
  - Below about 1 kHz, laptop speakers are weak. Above about 8 kHz, cheap microphones roll off. So both ends are avoided.
- **Tone shaping:** every symbol has a raised-cosine ramp to avoid clicks that spread energy into other tones.
- **Preamble:** an up-chirp followed by a down-chirp across the station's band. Correlation with the known chirps gives the start time. The difference between the two correlation peaks gives the frequency offset, and with it the clock drift.
- **Classic symbol decoder:** for each symbol window, an FFT, the energy in each tone bin, and a soft output (per-tone log-likelihood) passed on to error correction.

### 2. Framer, in `ggtf-core::frame`

```
| preamble | header (RS-protected) | payload blocks (RS + interleaved) | 
header:  version(4b) type(4b) | station_id(16b) | seq(8b) | ack(8b) | flags(8b) | len(8b) | crc16
payload: up to 64 bytes ciphertext + 16 byte AEAD tag, then crc32
```

- Frame types: `CALL`, `ANSWER`, `TRAIN`, `KEY`, `CONFIRM`, `DATA`, `ACK`, `NACK`, `BYE`.
- The header is small and protected with stronger error correction, so the receiver can read the length and type even when the payload is damaged.
- **Interleaving:** symbols are written into a matrix by row and sent by column, so a burst of noise hits many RS codewords a little instead of one codeword a lot.
- Erasures: symbols with low confidence (from the classic decoder or the ML model) are marked as erasures. Reed-Solomon can fix twice as many erasures as unknown errors.

### 3. Link layer, in `ggtf-core::link`

A pure state machine with no clock or audio inside. It takes events (`frame_received`, `tick(now)`, `send(bytes)`) and returns actions (`transmit(frame)`, `deliver(message)`, `status(...)`). This makes it fully testable in Rust and identical in every binding.

States: `Idle → Calling / Ringing → Training → KeyExchange → AwaitingConfirm → Connected → Closing → Idle`.

- **Half-duplex:** stop-and-wait ARQ. The sender transmits one frame, waits for the ACK, then sends the next. Turn-taking is enforced by the state machine, which has a `listening_for_reply` flag.
- **Full-duplex:** sliding window (initial size 4), with ACKs piggybacked on data frames in the other direction.
- **Timeouts:** the ACK timeout is computed from the frame airtime plus a margin. Retry limit 5, then fall back one profile, then end the session.
- **Training:** the caller sends a `TRAIN` burst in each profile, from slowest to fastest. The answerer reports which ones decoded and their SNR. Both pick the fastest profile with a clean decode and a margin.
- **Duplicate and replay protection:** a per-session sequence window. Frames with a sequence number already accepted are ACKed again but not delivered.
- **Self-filter:** frames whose `station_id` matches the local station are dropped before any processing.

### 3b. Beam mode and catch replies, in `ggtf-core::beam` and `ggtf-core::station`

Beams (Haunted QR) are connectionless: `BEAM` frames go to the broadcast address in a carousel of rounds.
Catch replies (Requirement 12) add a one-frame answer without making the beam a session:

- `BEAM_REPLY` (frame type 10) is header-only: `src` = receiver, `dst` = sender, `seq`/`ack` = beam id high/low byte.
  It uses the profile and band of the chunk it answers.
- **Sender:** after each round except the last, it leaves a 1.2 s reply window (`REPLY_WINDOW_MS`) before the next round.
  Carrier sense already holds transmission while any frame is arriving. Each reply heard pushes the window end to
  now + 1.2 s. Catchers are tracked per beam id and kept after the beam stops, so a reply to the final round still counts.
  With `stop_on_catch`, the first reply stops the beam.
- **Receiver:** a reply is queued only when the beam is complete *and* the chunk just heard is the last of its round,
  so it lands in the sender's window. Random delay 0-400 ms (`REPLY_JITTER_MS`) spreads several receivers apart.
  Any later chunk of that beam cancels a queued reply (the window has closed) and the next round's last chunk queues it
  again. At most 3 replies per beam (`MAX_REPLIES`). Replies can be switched off per station.
- Events: `BeamCaught { id, by }` on the sender, once per catching station.

### 4. Session security, in `ggtf-core::crypto`

1. Each station creates an ephemeral X25519 key pair per session.
2. The 32-byte public keys are exchanged in `KEY` frames.
3. HKDF-SHA256 derives two directional keys and a short authentication string (SAS) from the shared secret and both public keys.
4. Both screens show the SAS as 4 digits or 4 spooky words. The user confirms on both stations, then `CONFIRM` frames are exchanged. Until then, `DATA` frames are refused. This blocks a third station from sitting in the middle.
5. Data frames use ChaCha20-Poly1305. The nonce is built from the direction and sequence number, so it's never reused within a session.

The 16-byte tag per frame is a real cost on a slow link. It's accepted because security is required.

### 5. Channel simulator, in `ggtf-core::sim`

A chain of seeded, deterministic stages: `gain → clipping → reverb(IR) → add_noise(white @ SNR | sample buffer @ SNR) → dropouts → drift(resample by ppm) → mix(competing signal)`. It works on `f32` buffers at 48 kHz. Noise recordings and impulse responses are passed in as buffers, so the Rust core holds no datasets.

### 6. Feature extraction and ML decoder

- **Features (Rust, shared):** after preamble sync, each symbol window becomes a log-magnitude STFT patch covering the station's band, with a little context before and after. The same function is exposed in WASM and Python.
- **Model:** a small CNN (a few conv layers and a linear head). It outputs, for each tone group, a probability for each of the M tones. Target size under 1 MB, and fast enough to decode a symbol well within its airtime on a mid-range laptop.
- **Use in the pipeline:** the model replaces only the classic symbol decoder. Sync, deinterleaving, Reed-Solomon and CRC stay the same. The model's probabilities give confidence values, and low-confidence symbols become RS erasures.
- **Later option:** a second small model for preamble detection, only if the benchmark shows sync is the main failure point.

### 7. ML pipeline, in `ml/` (Python)

1. `generate.py` uses `ggtf_py` to encode random frames, then degrades them with the Rust simulator, mixing in noise buffers and impulse responses loaded from datasets. It saves features and labels in shards.
2. `train.py` trains the CNN in PyTorch, using a separate validation set with different noise recordings than training.
3. `export.py` exports to ONNX and checks that ONNX output matches PyTorch output within tolerance.
4. `bench.py` runs the scenario matrix for the classic decoder, the ML decoder (onnxruntime) and ggwave, and writes `ml/results/bench.json` and `ml/results/bench.md`.
5. Real recordings captured on the `/capture` page are added to the validation set, to check that training on simulated data works in real rooms.

**Candidate datasets** (each license is checked before use and recorded in `ml/datasets.md`): MUSAN (music, speech, noise), ESC-50 (environmental sounds), DEMAND (noise environments), OpenSLR room impulse responses.

### 8. Web app, in `apps/web`

- `/`: landing page explaining GGTF.
- `/link`: the main page. Call or Answer buttons, half/full-duplex switch, classic/ML decoder switch, SAS confirmation, chat, live spectrogram with bands marked, status panel.
- `/bench`: live benchmark. One tab sends a numbered test sequence, the other scores it, with BroadcastChannel used only to share ground truth.
- `/capture`: records labeled real-air sessions (WAV plus metadata) for the validation set.
- **Audio setup:** `getUserMedia({ audio: { echoCancellation: false, noiseSuppression: false, autoGainControl: false, channelCount: 1 } })`. The audio context requests 48 kHz and resamples if the browser can't provide it. Audio only starts after a user click.
- **UI components:** shadcn/ui throughout. Examples: `Card` for the status panel, `Dialog` for the SAS confirmation, `Tabs` for half/full-duplex, `Switch` for classic/ML decoder, `Badge` for message states, `ScrollArea` for chat, `Sonner` toasts for link events, `Table` for benchmark results, `Chart` for goodput and success-rate graphs. The spectrogram is a custom canvas component styled to match.
- **Style:** dark "haunted modem" theme, CRT glow, a ghost that appears on connect. Animations are reduced when `prefers-reduced-motion` is set. Text contrast meets WCAG AA.

## Error handling

| Situation | Behavior |
|---|---|
| Mic permission denied | Explain how to allow it; sending still works |
| Page not on HTTPS or localhost | Show that the mic needs a secure origin |
| Sample rate not 48 kHz | Resample, and show the real rate in the status panel |
| No cross-origin isolation | Fall back to `postMessage` and warn about extra latency |
| ML model fails to load or is too slow | Switch to the classic decoder and show a notice |
| CRC, RS or AEAD failure | Drop the frame, count it in the status panel, rely on ARQ |
| Retry limit reached | Fall back one profile, then end the session with a clear message |
| Idle timeout | End the session and show "the line went dead" |

## Testing strategy

- **Rust unit tests** for each module: tone generation, preamble correlation, RS, interleaving, header parsing, crypto, state transitions.
- **Rust property tests (`proptest`)** for the correctness properties below.
- **TypeScript tests (`bun test` + `fast-check`)** for the worker message protocol, ring buffer, resampler and UI state reducers.
- **Python tests (`pytest` + `hypothesis`)** for the bindings, feature parity with WASM, and ONNX export parity.
- **Benchmark** as the acceptance test for reliability and for the ML decoder.
- **Manual tests:** two tabs on one laptop, then two devices in a quiet and a noisy room.

## Correctness properties

1. **Round trip:** for any payload of 1 to 64 bytes and any profile, `decode(encode(payload)) == payload` on a clean channel.
2. **Noise tolerance:** for any payload, decoding through white noise at or above the profile's rated SNR returns the original payload.
3. **No silent corruption:** for any degraded input, the decoder returns either the exact original payload or an error, never a different payload.
4. **Burst tolerance:** any single dropout no longer than the profile's rated burst length is corrected.
5. **Deterministic simulator:** the same seed and settings always give identical output.
6. **Self-filter:** a station never delivers a frame carrying its own station ID.
7. **Exactly-once delivery:** for any sequence of frame losses, duplicates and reorders that the ARQ can recover, each message is delivered once, in order.
8. **Replay rejection:** a frame already accepted is never delivered again.
9. **Authentication:** any change to a ciphertext or header bit causes the frame to be rejected.
10. **Key agreement:** both stations always derive the same keys and the same SAS from the same exchanged public keys.
11. **Feature parity:** WASM and Python feature extraction give the same output for the same input, within float tolerance.
12. **Fragmentation:** splitting a message into frames and reassembling in order returns the original message.

## Performance targets (initial)

- Frame success rate ≥ 99% in the clean scenario and ≥ 90% at the agreed noisy SNR with the slowest profile.
- False preamble detections: fewer than 1 per 10 minutes of silence, speech or music.
- Decoding keeps up with real time on a mid-range laptop with the ML decoder enabled.
- Goodput is measured and reported against ggwave. Beating ggwave is a goal, not a requirement.
