# Build notes (working plan for the first build)

Scope of this build: Phase 0 to Phase 2 plus the simulator lab. ML (Phase 4), Python bindings and ggwave baseline (Phase 3), and full duplex (Phase 5) come later.

## Decisions taken while building (update design.md when stable)
- Modem: MFSK, 16 tones x 2 parallel groups, 4 bits per group per symbol. Goertzel per tone, no FFT for symbols.
  - wraith: window 1920, guard 480, base 1800 Hz, spacing 50 Hz, RS parity 24 (160 bps raw)
  - specter: window 960, guard 480, base 1500 Hz, spacing 100 Hz, RS parity 16 (267 bps raw)
  - banshee: window 480, guard 240, base 1500 Hz, spacing 100 Hz, RS parity 12 (533 bps raw)
  - Guard works like a cyclic prefix: echoes shorter than the guard don't hit the analysis window. Symbols crossfade over guard/4.
- Frame: chirp preamble 1500->4800 Hz (100 ms) + 10 ms gap + 2 wraith "marker" symbols that say which profile follows + header codeword + payload codeword.
  - Header: ver/type, src(2), dst(2), seq, ack, flags, len + CRC-16, RS parity 8 = 19 bytes.
  - Payload: bytes + CRC-32, RS parity from profile. One RS codeword each (frames are < 255 bytes), so no interleaving needed.
  - Low-confidence symbols become RS erasures; CRC decides which decode attempt is accepted.
- Receiver: 4th-order band-pass 1100-5600 Hz, FFT normalized correlation (rustfft, NFFT 8192) for the preamble, threshold 0.22.
- Link: half-duplex stop-and-wait. CALL -> ANSWER -> TRAIN x3 (slow to fast) -> TRAIN_RESULT -> KEY/KEY (X25519) -> SAS 4 spooky words -> CONFIRM (encrypted, reliable) -> chat.
  - ACKs are authenticated (AEAD tag of empty message). ACKs mirror the profile of the frame they answer.
  - 4 retries per profile, then fall back to a slower profile, then end the session.
  - Carrier sense: a station doesn't transmit while its receiver is in the middle of a frame.
- Browser: worklet and worker live in `apps/web/public/audio/` and load the WASM from `apps/web/public/wasm/`, so no bundler config is needed. Built WASM is committed so the app runs with only Bun.
- No SharedArrayBuffer for now: the worklet posts 2048-sample chunks straight to the worker through a MessageChannel.

## Bugs found while verifying
- Newer Chrome returns a Promise from `scrollIntoView`, so `useEffect(() => el.scrollIntoView())` handed React a non-function cleanup and crashed `/link`. Effects now use block bodies and scroll the boxes directly.

## Round 2 plan (user request: ML receiver with off switch, more bench, other frequencies, comfortable sound, replace QR codes)
- Bands: `Band::{Low, Mid, High}` with base 500 / 1500 / 14500 Hz. Every profile keeps its tone layout and is shifted by the band base.
  Each station runs one receiver per band, so it hears all bands at once. Replies use the band of the frame they answer.
- Comfort: output volume control in the worklet; High band (14.5–18 kHz) is far less audible; softer frame fade.
- Beam mode ("haunted QR"): connectionless broadcast of a short text/URL/Wi-Fi string, chunked into numbered BEAM frames
  with a message CRC, repeated in a carousel. Receivers assemble chunks from any round, in any order.
- ML receiver: per-symbol classifier on log tone-power features (sub-window slices + neighbour symbols).
  Training data generated by the Rust modem + simulator (example binary), trained in PyTorch, weights exported to a small
  binary file and run by Rust inside the WASM (no onnxruntime-web download); ONNX also exported for reference.
  Classic decoder stays the default; a switch turns ML on/off. Low-confidence ML outputs become RS erasures.
- Bench: harder rooms (lower SNR, louder talk/music, beeps 0 dB, long reverb, speaker roll-off), ML vs classic columns, per band.

## Round 2 results
- Bands, beam mode, ML receiver, volume, glare fix: built and tested (24 Rust tests, 7 Bun tests, WASM smoke, Chrome loopback incl. high-band beam with ML on).
- ML: 112 features, MLP 112-128-96-16 (28,400 params, 114 KB). Val symbol accuracy 89.8% classic → 91.6% ML.
  First model (trained without enough plain-hiss rooms) lost badly at -10/-14 dB hiss; fixed by (a) a third of training rooms
  being hiss down to -17 dB, (b) squaring the probability ratio so erasure confidence matches the classic scale, and
  (c) ML-then-classic fallback in the receiver (both CRC-checked, so the fallback can only add frames).
- Bench (210 cells, 20 frames): classic 89.6% / ML 92.2% overall; hard+brutal 83.2% / 87.4%. 0 corrupted frames accepted.
  Known failures: RT60 800 ms hall (all profiles), high band through a 7 kHz phone speaker.
- Real hardware (ASUS Vivobook, mic enhancements off): CALL rises +44 dB (mid) and +67 dB (high) over room noise at the mic.
- Deviation from design: inference runs in Rust inside the WASM (weights embedded), not onnxruntime-web. Same features code
  for training and live use, no extra multi-MB runtime. The ONNX file is still exported to ml/models/ for reference.
- Deviation: training data is generated by a Rust example binary instead of PyO3 bindings; Python only reads the files.

## Round 3: more data, faster, images
- New profile `poltergeist` (Turbo β): 3 tone groups × 16 tones, window 480 + guard 240, 800 bps raw. Marker tones moved to
  1/5/9/13 so four profiles are distinguishable. Band filters widened to fit its 4.7 kHz span.
- MAX_PAYLOAD 96 → 200. Payload RS parity now scales: base parity per 96 bytes, capped to fit a 255-byte codeword.
- Beam: chunk size 16–196 (UI: 48 or 196), messages up to 16 KB, binary-safe (base64 in WASM events), chunk map in progress events.
- Images: browser downscales to 48–128 px, WebP (JPEG fallback), 6-byte envelope `00 47 49 mime w h`.
- Measured:
  - sim, 3 KB: Fast/48 B 30 B/s, Fast/196 B 47 B/s, Turbo/196 B 68 B/s.
  - real air, mid band: 33-byte link in 1.2 s on Turbo; 928-byte image in 20.7 s (45 B/s) on Fast/196.
  - Turbo with long frames failed over real air (chunks 96 and 196), so the UI marks it experimental and moves images off Turbo.
- Bench now 252 cells: classic 86.9% / ML 90.0% overall; hard+brutal 79.1% / 84.0%; 0 corrupted frames.
- Model retrained with poltergeist symbols: val symbol accuracy 87.7% classic → 89.1% ML.

## Round 4: Séance OS (spec in `.kiro/specs/seance-os/`)
- Link: binary messages up to 12 KB tagged by kind; fragments of 56–176 B cut when sent and shrunk after retries; ACKs ride inside replies (DATA AAD now covers `ack` and `flags`); timers wait while a frame is arriving; growing random backoff; 45 s keep-alive; CALL tags; progress events.
- The line test no longer picks Turbo unless `set_turbo(true)`: over real air a 1 KB message took 51.7 s on Turbo and 37.5 s on Banshee.
- Measured over real air: app share (1,214 B) 28 s; Play together to playing about 30 s; game move 1.2–2.8 s; 1 KB letter 37.5 s.
